# 디렉터리·모듈 경계

> **상태:** 초안 — 접근 방식과 기반 논문이 정해지기 전이라 **모듈 경계는 미확정**이다.
> 이 문서에는 지금 지킬 수 있는 **원칙**만 적었다.
>
> 개발은 이미 시작됐고 6~8주차에 시험으로 중단되므로, 구체적인 패키지 구성은
> **1블록(3~5주차) 안에** 채운다 ([course.md](course.md) §3).

## 1. 왜 경계를 먼저 잡나

이 팀은 브랜치가 아니라 **경로 분리**로 충돌을 막는다. 기능마다 브랜치를 파고 PR을 반복하는
비용은 소규모 팀에서 이득보다 크고, 파일·모듈 경계가 흐리면 어떤 Git 방식을 써도 충돌은
반복된다. 그래서 **누가 어느 디렉터리를 맡는지**가 협업 규약
([collaboration.md](collaboration.md))보다 먼저다.

## 2. 원칙

| 원칙 | 설명 |
|---|---|
| **한 사람 = 한 경로** | 각자 "주로 건드리는" 디렉터리를 겹치지 않게 나눈다 |
| **공유 코어는 얇게** | 공용 메시지·설정·launch는 변경 빈도를 낮추고, 바꿀 때 합의한다 |
| **인터페이스 고정** | 각 모듈의 입력/출력을 문서화하고, 그 계약이 유지되면 내부 구현은 자유롭게 교체 |
| **대용량은 저장소 밖** | bag, dataset, 가중치, 맵 원본은 `../data/`에 둔다 |
| **호스트 경로 금지** | 코드·설정에 `/home/<사용자>/...`를 넣지 않는다 |

## 3. 최상위 구조 (확정)

```
2026-2-VIP3/
├── docs/       # 팀 공유 문서·연구노트
├── docker/     # 실행 환경
├── config/     # 파라미터
├── scripts/    # 실행 진입점
└── src/        # 코드 — 내부 구성은 §4
```

이 다섯 개는 스택과 무관하게 유지한다.

## 4. `src/` 모듈 구성 — 미확정

자율주차 시스템이라는 목표만 정해져 있고, 어떤 방식으로 풀지(고전 기하 기반 / 최적화 /
학습 기반)는 정하지 않았다. 방식에 따라 필요한 모듈이 달라지므로 지금 패키지를 미리 만들지
않는다.

확정할 때 결정할 것:

- [ ] 기능을 몇 개 모듈로 나눌지, 각 모듈의 입력/출력은 무엇인지
- [ ] 공용 메시지/자료구조를 둘지, 둔다면 어디에
- [ ] 시뮬레이터 연동 코드를 별도 모듈로 분리할지
- [ ] 모듈 하나당 담당자가 한 명씩 배정되는지 (겹치면 경계를 다시 나눈다)

결정되면 이 절을 실제 트리로 교체하고 §5 표를 채운다. **6~8주차 공백 전에 끝내는 것을
목표로 한다** — 구조가 정해져 있어야 공백 뒤에 각자 자기 경로에서 바로 재개할 수 있다.

## 5. 경로 오너십

| 영역 | 경로 | 담당 |
|---|---|---|
| 공용 infra | `docker/`, `scripts/`, `config/` | 미정 — 변경 전 공유 |
| 문서 | `docs/` | 전원 (연구노트는 각자 파일) |
| 코드 | `src/...` | **모듈 확정 후 배정** |

팀 구성이 정해지면 `미정`을 실제 담당자로 채운다. 그 뒤로는 **자기 경로 밖을 고칠 때만**
사전에 합의한다.
