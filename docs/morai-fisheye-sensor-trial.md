# MORAI 주차용 4어안 센서셋 — 첫 시험안

> **상태:** 2026-11-10 사용자 확인: Horizontal FOV 상한 179°, 4개 어안 출력 화면 확인. 전체 가시성·캘리브레이션은 미검증.
> **담당:** 안승현 센서셋 확정, 김동현 수신·수집, 하수영 SVM·인지.
> **차량:** 사용자 확정 `2023_Hyundai_ioniq5`. MORAI 공식 제원과 대조했으며 실제 mesh 가림·뒷바퀴축 원점의 지상고는 확인 필요.

권장 출발점은 **전·후·좌·우 어안 4대**다. 4대가 주차 SVM에 사용되는 논문 근거는 있지만, 우리 차량의 차체 바로 옆 노면까지 관측된다는 보장은 아니다. 먼저 근접 노면·네 모서리·카메라 겹침을 확인해 배치를 정한다. 부족하면 위치·각도·화각을 조정하고, 계속 남는 사각에 보조 카메라를 추가한다.

## 1. 논문에서 확인한 것과 우리 설계값

| 근거 | 직접 확인한 내용 | 적용할 부분 |
|---|---|---|
| [SS-PSD / CRPS-D, 2025, §III-A·Fig. 3](https://arxiv.org/html/2509.13133v1#S3.SS1) | 수집 장비에 어안 4대, 합성 영상은 10×10m·512×512 | 인지 입력의 영역·크기와 표현 |
| [AVM-SLAM, IROS 2024, §IV-A](https://arxiv.org/html/2309.08180v2#S4.SS1) | 어안 4대, 내부·외부 파라미터 보정, 왜곡 처리·IPM·BEV 합성 | 센서→SVM 생성 구조 |
| [AVM-SLAM 저자 데이터](https://yale-cv.github.io/avm-slam_dataset/) | 원본 어안 4뷰, 1280×960, 10Hz | 원본 해상도·전송률의 시작 참고 |
| [Click-Calib, 2025, §3](https://arxiv.org/html/2501.01557v3#S3) | 인접 영상에 함께 보이는 지면 대응점으로 외부 파라미터 정합. 내부 렌즈 모델/계수는 별도 필요 | 이음매 검증과 필요 시 외부 파라미터 보정 |

아래 XYZ·하향각·FOV 후보는 이 논문들이 제공한 최적값이 아니다. 차량 형상과 실제 관측을 보고 조정할 **프로젝트 시험값**이다. SS-PSD는 최종 BEV 한 장을 입력받으므로 카메라 수를 늘려도 모델 입력 채널 수는 그대로다. 다만 렌더링·전송·합성 비용은 증가한다.

### 해상도와 사이드미러 장착의 근거 구분

- **SS-PSD:** §III-A에서 `side-mirror-mounted fish-eye camera`라고 명시한다. 사이드미러 장착은 확인되지만 **미러의 아래쪽이라는 세부 위치·XYZ·높이·pitch는 본문과 Fig. 3에서 확인되지 않았다.** Fig. 3은 처리 장비·4개 카메라와 화면 예시이며 장착 부위의 확대 사진이 아니다. 512×512는 **합성된 BEV**의 해상도이고 원본 카메라 해상도는 이 원문에서 찾지 못했다.
- **AVM-SLAM:** §V-A에서 **원본 1280×960**, BEV 1354×1632, **두 영상 시퀀스의 저장률 10Hz**를 명시한다. 같은 절에서 실시간 BEV 합성은 30Hz라고 구분한다. [저자 데이터 설명 그림](https://yale-cv.github.io/avm-slam_dataset/img/information.png)도 원본·BEV 저장 규격을 확인해 주지만, 미러 아래의 장착 위치를 보여 주지는 않는다. §IV-A는 차량 주변 4대라고 설명하며 정확한 장착 부위·높이·각도는 확인되지 않았다.
- 따라서 **1280×960 원본은 AVM-SLAM, 512×512 BEV는 SS-PSD, 사이드미러 아래·외측은 우리 차량용 설계 제안**이다. 한 논문의 전체 센서셋을 그대로 재현한 설정이라고 설명하지 않는다.

## 2. 사용자 캡처에서 읽을 수 있는 값

첫 설정 캡처에는 `(X,Y,Z)=(3.80,0,0.40)`, `(Roll,Pitch,Yaw)=(0,0,0)`, `FishEyeCamera`, `Horizontal FOV=90`, `640×480`, `30Hz`, `Compression Ratio=90`, `Ground Truth=None`이 표시되어 있었다. 이후 사용자가 **이 환경의 Horizontal FOV 상한은 179°**라고 확인했고, 179°로 설정한 네 카메라의 출력 화면을 제공했다. 이후 시험은 **179°를 기준**으로 진행한다. 새 화면만으로 각 카메라의 현재 XYZ·pitch·원본 해상도는 확정할 수 없다.

- [MORAI 26.R1 센서 파라미터](https://help-morai-sim.scrollhelp.site/ko/morai-sim-drive/26.R1/-34)는 FishEyeCamera 모델과 설정 항목을 설명하지만, 해당 페이지에서 정확한 어안 투영식·FOV 변환식·현재 허용 범위를 확인하지 못했다.
- [과거 v4.3 공식 릴리스](https://morai-sim--drive-user-manual--en-22-r2.scrollhelp.site/msdume2/release-notes-v-4-3)의 180~360° 설명은 현재 환경에 적용하지 않는다. 종전의 180° 입력·190°/200° 비교 제안은 철회하고 사용자 확인값 179°로 수정한다.
- [MORAI 26.R1 위치 좌표계](https://help-morai-sim.scrollhelp.site/ko/morai-sim-drive/26.R1/-7)에 따르면 센서 원점은 **차량 뒷바퀴간 중심**이다. `Z=0.40`은 노면 위 40cm라는 뜻이 아니다. 평지에서 원점 높이를 `h_origin`이라 하면 센서 지상고는 `h_origin + Z`다.

179°라는 수치만으로 네 대의 근접 지면 관측이 충분하다고 판단하지 않는다. 새 화면에는 주변 주차선과 함께 하늘·차체 일부도 보인다. 이것만으로 렌즈가 잘못 설치되었다거나 차체 가까운 선이 전부 가려졌다고 판단할 수 없다. 각 원본의 유효 영역·차체 가림·공통 지면 점을 확인한다. 어안 수직 화각은 핀홀의 수평/수직 FOV 변환식으로 계산하지 않는다.

## 3. 먼저 적용해 볼 설정

### 공통

| UI 항목 | 첫 시험값 | 확인 사항 |
|---|---|---|
| Model | `FishEyeCamera` | 실제 렌즈 투영과 출력 유효 영역 확인 |
| Ground Truth | `None` | 주차칸 인지용 컬러 영상 |
| Width / Height | **1280 / 960** | 첫 연결만 640×480으로 확인해도 됨. 수집 규격은 선 해상도를 보고 고정 |
| Frame Rate | **10Hz** | 실제 수신율·타임스탬프 간격 측정. 저속 주차 개발의 시작값 |
| Compression Ratio | **90** | UI 값 유지, 주차선 주변 압축 손상 확인 |
| Horizontal FOV | **179°** | 사용자 확인 상한. 위치·각도·근접 가림·카메라 사이 겹침을 조정 |
| 통신 | ROS, 카메라별 다른 토픽·frame | 기존 rosbridge를 이용해 수신. 동일 주기는 동시 촬영 보장이 아님 |

FOV를 179°로 유지하고 원본의 유효 해상도와 차체 가림으로 위치·각도를 판단한다. 1280×960·10Hz는 프로젝트 시작 제안이며 AVM-SLAM의 10Hz는 저장 규격이다. 현재 하드웨어에서 이 전송·처리율이 실측되었다는 뜻은 아니다.

### 배치·자세

높이는 **노면 위 렌즈 높이**다. 실제 UI의 Z에는 원점 높이를 빼서 입력한다. 팀 좌표 약속은 x 전방·y 좌측·z 위다. 아래 pitch는 현재 팀 코드의 양수=하향 규칙이며 View에서 실제로 아래를 향하는지 확인한다.

| 카메라 | 위치 | 지상고 시작값 | Roll | Pitch | Yaw |
|---|---|---:|---:|---:|---:|
| 전방 | 전면 범퍼/그릴 중앙, 렌즈가 차체에 가리지 않는 외측 | 1.00m | 0° | **35° 하향** | 0° |
| 후방 | 후면 번호판/테일게이트 중앙 외측 | 1.00m | 0° | **35° 하향** | 180° |
| 좌측 | 좌측 사이드미러 아래·외측 | 1.20m | 0° | **45° 하향** | 90° |
| 우측 | 우측 사이드미러 아래·외측 | 1.20m | 0° | **45° 하향** | 270°（−90°와 동일） |

우선 하향각을 전후 25~45°, 측면 35~55°에서 조정한다. 예를 들어 높이 1m인 렌즈에서 수평거리 0.2m의 지면은 수평보다 약 78.7° 아래에 있다. 따라서 먼 풍경이 잘 보이는 수평 카메라가 바로 옆 주차선을 잘 보는 것은 아니다. 각도 조정은 실제 수직 시야와 함께 판단한다.

### XYZ가 필요한 경우의 조건부 예시

[MORAI 26.R1 공식 차량 제원](https://help-morai-sim.scrollhelp.site/ko/morai-sim-drive/26.R1/vehicle-specification)의 Ioniq5는 길이 4.635m, 폭 1.892m, 축거 3.0m, 앞/뒤 오버행 0.845/0.790m다. 뒷바퀴축 원점 기준 단순 외곽은 계산상 `x=[−0.790,3.845]m`, `y=[−0.946,0.946]m`가 된다. 이 직사각형은 실제 외판·미러 형상 모델이 아니다.

아래 Z는 **뒷바퀴축 원점이 노면 위 0.35m라는 가정**(`ground_z=−0.35m`)을 사용한다. 실제 원점 높이가 다르면 목표 지상고 1.0/1.2m를 유지하도록 Z를 바꾼다. 최종 좌표가 아니며 특히 범퍼/미러 내부에 렌즈가 들어가면 위치를 조정한다.

| 카메라 | X | Y | Z | Roll / Pitch / Yaw |
|---|---:|---:|---:|---|
| 전방 | 3.90 | 0.00 | 0.65 | 0 / 35 / 0 |
| 후방 | −0.85 | 0.00 | 0.65 | 0 / 35 / 180 |
| 좌측 | 2.40 | 1.05 | 0.85 | 0 / 45 / 90 |
| 우측 | 2.40 | −1.05 | 0.85 | 0 / 45 / 270 |

실제 장착 부위가 이 직사각형 외곽과 다르면 전방 X는 실제 전면 끝 바깥, 후방 X는 후면 끝 바깥, 측면 Y는 실제 외판/미러 바깥으로 다시 정한다. 기존의 핀홀 140° 후보와 이번 어안 179° 후보는 서로 다른 렌즈 가정이므로 가시성 계산 결과를 공유하지 않는다.

## 4. 4대가 충분한지 판단하는 시험

정적·평탄한 주차칸 002 또는 008 주변에서 먼저 확인한다. 다음 값은 논문 성능 기준이 아닌 프로젝트 확인 절차다.

1. **카메라 1대로 렌즈·좌표 확인:** FOV 179°의 View·원본·export를 기록한다. Pitch를 소폭 바꿔 하향 부호를 확인한다. 외판과 렌즈의 위치를 확인한다. 화면 창의 크기를 원본 해상도로 간주하지 않는다.
2. **네 원본 영상에서 근접 노면 확인:** 차체 둘레 0.1/0.2/0.3/0.5/1/2m 지면의 주차선·확인점을 본다. 실제 mesh에 가려진 구간은 미관측으로 기록한다.
3. **네 모서리의 겹침 확인:** 전방–좌측, 전방–우측, 후방–좌측, 후방–우측 각각에 같은 지면 점이 보여야 한다. 앞바퀴 옆만 보이고 뒷바퀴 옆이 빠지는지도 확인한다.
4. **시험 BEV 확인:** 차체 마스크 밖 10×10m 영역에서 유효 관측 mask를 만들고, 주차선이 이음매에서 갈라지거나 꺾이는지 확인한다. 카메라별 원본과 합성 영상을 함께 보관한다. 격자·검출 표시 없는 영상을 모델에 넣는다.
5. **대수 결정:** 원본에 점이 안 보이면 배치/화각 문제다. 원본에는 보이고 BEV에서 어긋나면 캘리브레이션/투영 문제다. 배치 조정 후에도 필요한 후측면 구간이 안 보이면 그 구간을 향한 보조 카메라 2대, 총 6대를 비교한다. 두 대 추가만으로 모든 사각이 사라진다고 가정하지 않는다.

현재 UI만으로 실제 커버리지 비율을 계산하지 않았다. 종전 핀홀 분석의 100% 값은 차체 가림을 제외한 일부 표본의 계산값으로, 이번 어안 배치의 성공률로 사용할 수 없다.

## 5. 하수영의 SVM 구현과 김동현의 수집

현재 [calibration.py](../src/perception/drivable_bev/src/drivable_bev/calibration.py)는 핀홀 내부 행렬과 homography를 사용한다. **179°는 FOV 범위 검사를 통과하지만 어안 영상에 핀홀 식을 적용하는 오류는 그대로 남는다.** 어안인지 여부는 180°라는 임계값으로 판별할 수 없고 실제 투영 모델로 정해야 한다.

권장 구현은 **BEV 지면 점 → 카메라 좌표 → 실제 어안 투영식 → 원본 픽셀**의 remap을 미리 계산해 영상마다 재사용하는 방식이다. AVM-SLAM의 왜곡 처리→IPM 구조를 참고하되, 좁은 가상 핀홀 영상으로 먼저 잘라 필요한 주변 시야를 버리지 않도록 한다. MORAI FishEyeCamera가 OpenCV의 특정 어안 모델과 같거나 왜곡 계수가 0이라고 가정하지 않는다.

렌즈 투영식·내부 파라미터가 export나 기술 문서에서 확보되지 않으면 알려진 대응점으로 캘리브레이션하고 별도 점에서 오차를 검증해야 한다. Click-Calib은 내부 모델을 대신 알아내는 방법이 아니다. 초기 검증에서 어안 투영을 확보하지 못하면 [기존 설계의 광각 핀홀 후보](ss-psd-sensor-bev-baseline.md)를 일정상 대안으로 평가한다.

김동현은 원본 이미지·원본 시각·차량 상태·센서 JSON을 같은 run으로 수집한다. 각 카메라를 10Hz로 설정해도 동기화는 별도 확인한다. 안승현이 센서 위치를 바꾸면 하수영의 투영 파라미터와 김동현의 설정 버전을 함께 갱신한다.

최종 모델 입력은 **10×10m·512×512**, 차량 전방이 위, 현재 코드 기준 BGR 순서다. 차량 중심과 뒷바퀴축 원점의 offset을 기록한다. 관측되지 않는 지면을 이미지 생성·inpainting으로 채워 학습 입력으로 쓰지 않는다.

초기 센서셋은 카메라 4대와 차량 상태 채널로 시작할 수 있다. `/Ego_topic` 기반 odom을 사용한다면 자차 위치는 시뮬 GT 사용이라고 명시한다. IMU/GPS/LiDAR는 상태추정·장애물 확인 등 구체적으로 사용하는 기능이 생길 때 추가하며 SS-PSD에 필수 입력이라고 설명하지 않는다. 초기 주차는 비어 있음을 확인한 정적 칸에서 진행한다.

- 네 카메라의 export JSON, 같은 정차 자세의 원본 영상, 근접 관측·겹침 확인 기록.
- 확인된 렌즈 모델/파라미터 또는 아직 필요한 정보, 수신율·원본 시각 확인 결과.

이 문서는 사용자 확인값과 출력 화면을 반영한 설정 시험안이다. 실제 MORAI JSON의 어안 모델 번호·캘리브레이션 값을 추측해 생성하지 않았으며, 센서 JSON·TF·런치·BEV 구현은 변경하지 않았다.
