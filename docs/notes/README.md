# 팀 작업 노트

각자 **작업을 마칠 때 5분 정도** 써서 결과·막힌 점·다음 할 일을 남긴다. 안승현은 기술 상태와 인수인계를 확인하고, 장원태는 이 기록의 그림·수치·실행 근거를 발표자료에 사용한다. 코드를 작성하지 않은 조사·센서 설정·통합·발표 작업도 기록한다.

## 작성 방법

1. [TEMPLATE.md](TEMPLATE.md)를 복사해 `YYMMDD-이름.md`로 저장한다. 예: `261112-donghyun.md`. 같은 날 작업은 같은 파일에 추가한다. 이름 표기는 `seunghyun`, `wontae`, `donggyun`, `donghyun`, `suyoung`을 사용한다.
2. **한 일 / 코드·입력·명령 / 결과·증거 / 막힌 점·다음 작업**을 채운다. 실행하지 못한 것은 미검증으로 적고, 자료가 없으면 없다고 남긴다.
3. 코드 변경이 있으면 같은 커밋·PR에 넣고, 문서만 쓴 날도 커밋한다. 실행 방법이 달라지면 [commands.md](../commands.md), 공통 일정·역할 변경은 [계획](../project/plan.md)·[오너십](../project/team.md)도 갱신한다.
4. 이 페이지의 최신 기록 표에 한 줄을 추가한다. 다른 사람의 기록을 덮어쓰지 않고, 정정은 날짜와 근거를 덧붙인다.

새 노트는 날짜를 기준으로 한다. 복원한 `w04`, `w05`, `w09`는 **학기 주차**를 쓴 과거 파일명이며, 현재 자율주차 **5주 구현 계획의 주차와 다르다**.

## 안승현·장원태의 확인과 발표 활용

| 확인자 | 노트에서 확인할 것 | 남길 내용 |
|---|---|---|
| 안승현 | 코드·설정·재현 명령, 파트 간 입력/출력, 미해결 문제 | 기술 확인 범위와 다음 담당자. 확인 전이면 그대로 표시 |
| 장원태 | 발표에 쓸 한 문장, 그림/영상/표, 측정 조건과 한계 | 사용할 자료 링크·발표 위치, 추가로 필요한 자료 |

성공률은 성공 횟수/전체 시도 수와 조건을 함께 쓴다. 테스트 통과·정차 캡처 정합·실제 자율주차 성공을 구분한다. 계획은 계획으로 표시하고, 발표 수치는 원본 노트·커밋·결과 파일로 되짚을 수 있게 연결한다. 확인 메모는 각 노트의 마지막 칸에 추가한다.

## 자료 위치

- 작업 노트와 팀에 필요한 작은 결과 표·JSON·대표 이미지는 이 폴더에 둔다. 파일은 `evidence/YYMMDD-내용.*`로 연결한다.
- bag·대량 원본 영상·모델 가중치는 Git에 넣지 않는다. run ID, 설정/코드 버전, 필요하면 SHA-256과 팀원이 접근할 수 있는 전달 위치를 적는다. 개인 로컬 경로만 있으면 **공유 전·보유자**를 명시한다.
- 개인 연구 상세와 구버전 문서 보관은 저장소 밖 `../docs`를 사용한다. **팀원의 작업 이력과 인수인계 노트는 팀 repo에 유지한다.**

현행 구현 상태는 [개발 계획](../project/plan.md), 구조는 [src 문서](../project/src-refactoring.md), 재현 명령은 [commands.md](../commands.md)가 기준이다.
