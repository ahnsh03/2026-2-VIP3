# 작업 기록

매주 각자 무엇을 했는지 남긴다. **12·13·14주차에 주간 진행 점검**이 있고 15주차에 최종
보고서를 내야 하므로 ([../course.md](../course.md) §4), 그때 재료가 되도록 미리 쌓아 둔다.

특히 **개발이 끊기는 주차 직전**(5주차 말, 9주차 말)에는 반드시 남긴다. 6~8주차 시험 기간을
지나 돌아오면 무엇을 하다 멈췄는지 기억나지 않는다 — 그 복귀 비용을 줄이는 게 이 기록의
가장 실질적인 용도다.

> 강의계획서에 "연구노트"가 평가 항목으로 명시돼 있지는 않다. 다만 과제 40% · 토론 10% ·
> 기타 10%의 구체적 내용이 아직 확인되지 않았고, 사업단 공통 VIP 평가도구에는 연구노트와
> 동료평가가 포함된다. 확인되면 [../course.md](../course.md) §5(평가)와 함께 갱신한다.

## 규칙

| 항목 | 기준 |
|---|---|
| 파일 이름 | `주차-이름.md` — 예: `w12-seunghyun.md` |
| 주기 | **매주 1개**, 각자 작성 |
| 분량 | 길 필요 없다. 무엇을 했고 다음에 뭘 할지가 남으면 된다 |
| 팀 미팅 | 그 주 담당자가 `w12-meeting.md`로 따로 남긴다 |

[TEMPLATE.md](TEMPLATE.md)를 복사해서 쓴다.

## 왜 저장소에 두나

- 커밋 히스토리와 함께 보면 **누가 무엇을 했는지**가 그대로 남는다
- 주간 점검·최종보고서를 쓸 때 다시 기억을 짜내지 않아도 된다
- 다음 학기 수강생이 참조할 기록이 된다

개인 정보, 계정, 라이선스 키는 적지 않는다.
