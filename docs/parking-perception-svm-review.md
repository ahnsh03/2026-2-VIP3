# DMPR-PS·SS-PSD 비교와 근접 주차선용 SVM 설계 검토

> **문서 역할:** 제안 — 팀원이 제시한 논문·추가 의견 검증과 센서 재설계 근거
> **담당:** 팀 공동 검토용 — 인지·센서 담당 참고
> **최종 수정:** 2026-11-10

**2026-11-10 결정:** 사용자가 **SS-PSD를 주 기준선으로 채택하고 공개 가중치와 직접 수집·주석한 MORAI 데이터의 추가 학습을 비교**하기로 했다. DMPR-PS는 비교·참고용이다. 두 공식 클론을 확보했고, 최신 센서·BEV·수집 설계는 [SS-PSD 센서·BEV 기준](ss-psd-sensor-bev-baseline.md)을 따른다. 아래 모델 선정 비교는 10월 27일 검토 기록이다.

현재 권고는 **SVM을 새로 설계하고, DMPR-PS와 SS-PSD 공개 가중치를 같은 MORAI 영상에서 먼저 비교**하는 것이다. 인지 구현 기준선은 DMPR-PS, 2024년 이후 연구 후보는 SS-PSD로 둔다. 이전에 추천한 Two-Stage의 YOLO 재학습보다 공개 슬롯 가중치를 먼저 시험하는 편이 총 75인시에서 데이터 준비 부담을 줄일 수 있다. 비교 결과에 따라 한 모델만 최종 시스템에 연결한다.

기존 v1 센서셋은 다른 프로젝트에서 가져온 임시 구성이다. 저장소의 v2 SVM 프리셋도 수학적 가정으로 만든 후보이며 실제 차량·렌즈·가림에 대해 검증된 최종 설정이 아니다. 기존 위치·각도·FOV를 제약으로 유지하지 않는다. 이 검토에서는 실제 센서 JSON·TF·런치 설정을 변경하지 않았다.

## 1. 팀원이 가져온 두 논문의 관계

| 역할 | 방향 표식 점 회귀와 기하 pairing의 구현 기준선 | 데이터셋 확장과 반지도 학습을 적용한 최근 비교 모델 |

근거: [DMPR-PS 공식 서지](https://ieeexplore.ieee.org/document/8784735/), [논문 PDF·저자 코드](https://github.com/Teoge/DMPR-PS), [SS-PSD 논문](https://arxiv.org/html/2509.13133v1), [게재 DOI](https://doi.org/10.1109/TITS.2025.3612466), [저자 코드](https://github.com/zzh362/CRPS-D). T-ITS 권·호·페이지는 DOI 등록 메타데이터에서도 확인했다. 이전 계획에 arXiv만 표시했던 서지를 보완한다.

**관계는 “DMPR 계열 표식 표현 + 더 다양한 데이터 + 반지도 학습 확장”으로 이해하면 된다.** SS-PSD는 점 검출 대신 완전히 다른 4코너 end-to-end 문제를 푸는 모델이 아니다. CRPS-D는 데이터셋 이름이고 SS-PSD가 방법 이름이다. 추론에는 공개 코드상 단일 TeacherDetector를 사용한다. teacher와 student를 함께 쓰는 학습 비용을 추론 비용으로 오해하지 않는다.

### 두 모델에 공통으로 필요한 보완

- **입구 두 점과 방향 ≠ 네 코너의 독립 관측.** DMPR-PS는 슬롯 깊이를 사전 지식으로 가정하며, 공개 추론 코드는 정해진 길이로 측면을 연장한다. SS-PSD의 그림 출력에도 길이 상수가 있다. 슬롯 깊이를 영상에서 추가 측정하거나 공통 prior를 명시해야 한다. 대상별 GT 깊이·중심을 넣어서 완성하면 인지 평가가 오염된다.
- **슬롯 인지 ≠ 빈 칸 판정.** 두 모델만으로 차량·물체가 없는 주차 가능한 공간인지 판단했다고 보고하지 않는다. 초기에는 비어 있음을 확인한 시나리오로 평가하고, 점유 판정은 별도 모듈·주석·지표가 있을 때 추가한다.
- **합성 영상의 스케일이 계약이다.** 카메라 수보다 차량 방향·위치, 지면 m/px, 렌즈 처리, 이음매, 차체 마스크가 중요하다. 20×16m BEV를 단순히 512×512로 늘리는 방식은 피한다. 원본 픽셀→차량 좌표를 보존하며 모델에 맞는 영역을 crop한다.
- **5개 슬롯의 좌표 GT가 표식 라벨은 아니다.** L/T 접점의 정의, 입구 변, 방향을 영상과 대조한다. 기존 JSON은 사용자 의도대로 평가와 제어 개발에 쓰며, 학습 영상은 별도로 주석한다.

### 코드와 하드웨어에서 확인한 것

DMPR-PS는 데이터 준비·방향 라벨·평가 절차가 비교적 명확하다. 다만 오래된 코드의 환경 의존성과 장치·입력 경로는 실제 실행에서 확인해야 한다. 공개 가중치가 있다는 사실만으로 MORAI 영상에서 충분한 성능이 나온다고 보장하지 않는다.

SS-PSD 공개 `inference.py`에는 `cuda:4`와 개인 이미지 경로가 고정되어 있다. 입력 resize가 주석 처리되어 있으므로 어댑터에서 shape·색 순서를 맞춰야 한다. `train.py`의 사전학습 가중치 로드 부분도 주석 상태여서 README의 실행 명령만으로 fine-tuning이 완성되지는 않는다. [추론 코드](https://github.com/zzh362/CRPS-D/blob/main/inference.py), [학습 코드](https://github.com/zzh362/CRPS-D/blob/main/train.py)

RTX 4060 8GB·노트북 3060 6GB에서는 우선 **추론 batch 1**, 이후 필요한 모델 하나만 작업별 fine-tuning을 검토한다. 학습은 optimizer step을 포함한 100 step의 peak VRAM·시간을 먼저 측정한다. SS-PSD의 반지도 학습은 두 모델과 추가 forward/backward를 포함하므로 일반 지도 fine-tuning보다 부담이 크다. 작은 batch·AMP는 조정 후보이며 적합성의 측정 결과가 아니다. 수집과 학습을 나누고 같은 GPU에서 MORAI 렌더링과 학습을 동시에 실행하는 것을 기본 전제로 하지 않는다.

## 3. SVM 센서 재설계에 읽을 논문

이 논문들은 **센서 구성·투영·캘리브레이션 방법**을 제공한다. 우리 차량에 최적인 XYZ·pitch·FOV를 대신 정해 주지는 않는다. 카메라 배치 문제와 이미 설치한 카메라의 파라미터 보정 문제를 구분한다.

| 우선 | 논문 | 읽을 부분·이번 적용 |
|---|---|---|
| **1 · 전체 구성** | **AVM-SLAM: Semantic Visual SLAM with Multi-Sensor Fusion in a Bird’s Eye View for Automated Valet Parking**, IROS **2024**; 최초 preprint 2023 | §IV-A의 4어안→왜곡 처리→IPM→합성 BEV. 카메라 1280×960, 저장 데이터 10Hz의 실제 사례. 전체 SLAM을 구현할 필요는 없음. [원문](https://arxiv.org/html/2309.08180v2), [저자 데이터](https://yale-cv.github.io/avm-slam_dataset/) |
| **2 · 캘리브레이션 구현** | **Click-Calib: A Robust Extrinsic Calibration Method for Surround-View Systems**, **2025 preprint** | 인접 카메라의 겹치는 지면 점을 클릭해 외부 파라미터 최적화. 코드·예제 공개, 신경망 학습 불필요. [원문](https://arxiv.org/html/2501.01557v3), [코드](https://github.com/LihaoWang1991/click_calib) |
| **3 · 정합 평가** | **Camera calibration for the surround-view system: a benchmark and dataset**, The Visual Computer **2024** | 전후 영상의 선, 측면과 인접 카메라의 지면 영상·edge 정합을 활용. 정확한 파라미터와 겹침이 필요한 이유를 학습. [원문](https://link.springer.com/article/10.1007/s00371-024-03275-9) |
| **4 · 렌즈·시뮬 차이** | **Surround-View Fisheye Optics in Computer Vision and Simulation: Survey and Challenges**, **2024** | 초광각의 기하 왜곡·주변부 품질·시뮬레이션 모델 차이. 넓은 FOV 핀홀을 실제 어안과 동일 취급하지 않기 위한 참고. [원문](https://arxiv.org/html/2402.12041v2) |

Click-Calib은 내부 파라미터와 초기 외부 파라미터가 필요하고, 물리 스케일을 고정하기 위해 카메라 높이를 사용한다. 저자 코드는 인접 카메라 쌍당 지면 대응점 10개 이상을 권한다. 실제 MORAI 투영 모델에 맞는 projection/unprojection을 사용해야 하며 WoodScape의 어안식을 그대로 복사하지 않는다. MORAI에서 파라미터가 알려져 있다면 먼저 그 값으로 투영을 검증하고, 캘리브레이션 최적화는 필요할 때 적용한다.

MORAI 공식 센서 문서는 **Camera / Fish Eye Camera / Physical Camera**를 구분한다. 따라서 어안 지원을 미확인으로만 남겨 놓고 핀홀 150°를 최종안으로 정하는 것은 맞지 않는다. 사용 중인 버전의 UI·출력과 투영 규칙을 확인해야 한다. 문서에 어안 옵션이 있다는 사실만으로 특정 JSON의 modelType 번호, 실제 투영식·FOV 범위까지 확인된 것은 아니다. [MORAI 공식 Sensors](https://help-morai-sim-en.scrollhelp.site/morai-sim-standard-en/sensors)

## 4. 차 바로 옆의 선을 보기 위한 설계

우선 **앞범퍼/그릴·뒷범퍼/번호판·좌우 사이드미러 아래의 4카메라**를 시작 구성으로 삼는다. 차체를 내려다보는 루프 카메라보다 차체 외곽에서 지면을 직접 볼 수 있는 위치를 탐색한다. 최종 XYZ는 실제 차량 mesh와 좌표 기준에 맞춰 정하며 다른 차의 좌표를 복사하지 않는다.

| 항목 | 제안·측정할 것 |
|---|---|
| 관측 목표 | **차체 외곽에서** 0.1·0.2·0.3·0.5·1·2m 떨어진 지면과 실제 표식. 좌우 모두 차량 길이를 따라 확인 |
| 앞뒤 관측 | 입구를 찾는 접근 단계의 수 m 지면과 주차 종료 단계의 범퍼 가까운 지면을 함께 확인 |
| 겹침 | 전좌·전우·후좌·후우 이음매에서 동일한 지면 선·점이 인접 2대에 관측되는지 확인 |
| 위치·높이 | 차체·미러·범퍼가 광선을 막지 않는 위치. 높이를 낮추는 것만으로 최적이라고 판정하지 않음 |
| pitch·FOV | 실제 렌즈 투영에 맞춰 후보를 탐색. 수평 FOV뿐 아니라 수직 FOV, 종횡비와 하향각을 함께 고려 |
| 해상도·주기 | 640×480·10Hz는 첫 통신 시험 후보. 1280×960과 선의 원본 픽셀 폭·미검출·지연을 비교하고 선택 |
| BEV | 유효 관측 마스크, 차체 마스크, 겹침 오차, m/px 유지. 확대 보간한 영상이 원본 관측 정보를 늘리지는 않음 |
| 검증 장소 | 002/008에서 설계·검증. 009에서 별도 확인, 012의 높이 특성은 따로 분석. 039까지 좁은 칸 조건 확대 |

예를 들어 차폭이 **가정상 1.9m**이고 칸 폭이 2.30m라면 중앙 정렬 시 좌우 여유가 약 0.20m다. 이것이 차량 중심 반경 1m의 가시율보다 **차체 바깥 0.20m 지면의 관측 여부**가 중요한 이유다. 1.9m는 실제 선택 차량의 확인값이 아니다.

핀홀 카메라의 수직 단면을 예로 들면, 카메라 높이가 h이고 광학 중심 바로 아래 지점에서 바깥쪽으로 d만큼 떨어진 지면을 보는 하향각은 `atan2(h,d)`다. 하향 pitch가 α, 수직 반각이 β라면 `|atan2(h,d)−α| ≤ β`를 만족해야 한다. 이는 수평 화각과 차체 가림을 제외한 필요 검토 조건이다. 핀홀·정사각 픽셀·중앙 주점 가정에서 `β=atan((H/W)tan(HFOV/2))`이며 어안에는 이 식을 그대로 적용하지 않는다.

카메라가 차체 바깥으로 돌출되면 d와 차체에서 선까지의 거리는 다르다. 카메라 바로 아래 지면을 볼 조건 `α+β≥90°`도 전체 360° 관측·차체 무가림을 보장하지 않는다. 특정 프리셋 탐색 결과만으로 “FOV 130° 미만이면 SVM 불가능”이라고 결론 내리지 않는다.

**센서 배치 → 실제 RGB 가시성 → 투영·스티칭 검증 → 검출기 평가** 순서로 진행한다. 카메라에 들어오지 않은 선은 캘리브레이션이나 좋은 검출기로 복구할 수 없다. 검출 실패를 센서 미관측, 투영 불일치, 모델 실패로 나눠 기록한다.

### 카메라가 반드시 4대여야 하는가

DMPR-PS와 SS-PSD는 **이미 합성한 RGB 한 장**을 입력받는다. 합성에 카메라 5~6대를 썼다는 이유만으로 신경망 입력 차원이나 가중치 호환성이 깨지지는 않는다. 다만 이음매·질감·스케일·차체 마스크가 바뀌면 도메인 차이가 생긴다. 4대는 일반적인 시작 구성과 공수 절감의 선택이며, 아키텍처의 절대 제약이 아니다.

따라서 4대에서 실제 사각이 남으면 위치·자세·렌즈·해상도를 조정하고, 해결되지 않는 구역에 보조 카메라를 검토할 수 있다. 이때 전송·합성 비용은 증가하지만 **SVM 한 장을 처리하는 검출기의 호출 횟수가 카메라 수에 비례해 늘지는 않는다.** 기존 문서의 카메라별 추론 가정 수치를 그대로 적용하지 않는다.

## 5. 75인시에서의 채택 순서

1. **센서·BEV 팀:** 현재 센서값을 최종안으로 쓰지 않고 실제 차량 외곽의 4뷰를 재설계한다. 주차선과 알려진 길이 격자로 가까운 지면·이음매·물리 스케일을 확인한다.
2. **인지 팀:** 센서 완료 전에는 공개 샘플로 DMPR-PS를 먼저 실행한다. 이후 같은 수집 시퀀스로 DMPR-PS와 SS-PSD의 공개 가중치를 평가한다. 다운로드 성공·weights hash·입력 변환·장치·지연을 기록한다.
3. **제어 팀:** 제공 GT 목표로 경로·추종·정지를 계속 개발하고, 인지가 준비되면 같은 목표 계약으로 전환한다.
4. **평가 팀:** 슬롯 검출 P/R 외에 입구 점 오차·방향 오차·목표 흔들림·미검출·종단 주차 성공을 측정한다. GT 목표와 인지 목표의 실행을 분리한다.
5. **모델 확정:** 더 나은 최신 모델을 미리 단정하지 않는다. 같은 시퀀스에서의 오차·지연·실패를 보고 한 모델을 선택한다. fine-tuning은 그 후 필요한 경우 한 모델에만 수행한다.

비교 가중치의 학습 데이터가 서로 다르다는 한계를 발표에 명시한다. 학습 기여의 통제 실험을 추가할 시간이 없다면 공개 모델 적용 비교와 센서·투영·인지·주차의 오류 분석으로 범위를 명확하게 보고한다.

이 문서는 원문·공개 소스·서지를 검토한 결과다. 실제 모델 가중치 다운로드·실행, 6GB/8GB 학습 측정, MORAI 카메라 설정 및 주차 실험은 아직 수행하지 않았다.
