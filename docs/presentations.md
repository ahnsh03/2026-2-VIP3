## 0. 공통 — 세 번 다 해당

### 5~10분은 생각보다 훨씬 짧다

여유를 두면 **실질 7분**이고 슬라이드 8장, 장당 **40~60초**다.
**전부 설명하려다 아무것도 전달 못 하는 것**이 이 분량에서 가장 흔한 실패다.

한 발표에 **전달할 것 두 개만** 정한다. 나머지는 질문받으면 답한다.

### 자료는 개발하면서 확보한다 — 나중에 못 만든다

발표 준비 기간에 시뮬레이터를 다시 띄워 화면을 재현하려면, 그때 연결이 안 되거나
설정이 바뀌어 있으면 **자료 자체가 없어진다.** 10/05~10/13 은 시험 기간이기도 하다.

**되는 순간 바로 찍는다.**

| 자료 | 언제 | 어디에 |
|---|---|---|
| 스크린샷 (RViz, BEV, 검출 결과) | 되는 순간 | `docs/images/` — 저장소에 커밋 |
| 화면 녹화 (시연 30초 내외) | 되는 순간 | **저장소 밖.** 용량이 커서 git 에 넣지 않는다 |
| 숫자 (오차, 성공률, 처리 주기) | 측정하는 순간 | `docs/notes/` 주간 기록 |

> 영상은 **재생 실패를 전제**한다. PPT 에 임베드하되 **스틸 3장(시작–중간–끝)을 따로**
> 준비해 둔다. 발표장 PC 에서 코덱이 없어 안 돌아가는 일이 흔하다.

### 슬라이드에 글을 넣지 않는다

대본이 따로 있다. 슬라이드는 **그림 한 장 + 제목 한 줄 + 숫자 몇 개**가 기본이고,
읽을 문장을 넣으면 청중이 발표자를 안 본다.

## 1. 중간발표-1 (10/13) — 슬라이드 설계

**전달할 것 두 개:**

1. **다섯 명이 각자 무엇을 맡고 있고, 그게 어떻게 하나로 이어지는가**
2. **지금 무엇이 돌아가는가** (말이 아니라 화면으로)

범위를 좁힌 것(칸 하나 지정)을 **변명하지 않는다.** 7주에 무엇을 확실히 끝낼지
정한 결과이고, 그렇게 말하는 편이 오히려 설득력이 있다.

### 슬라이드 8장

| # | 제목 | 여기서 말할 것 | 필요한 자료 | 만드는 사람 |
|---:|---|---|---|---|
| 1 | 표지 | 팀·주제 한 줄·팀원 5명 | — | 안승현 |
| 2 | **무엇을 만드는가** | KATRI 주차장에서 **지정한 칸 하나**를 인식해 자동 주차. **빈 칸 탐색은 범위 밖** | 주차장 맵 그림 + 지정 칸 표시 | 강도균 |
| 3 | **왜 이렇게 좁혔나** | 개발 가능 주가 7주. 칸 선택까지 하면 **틀렸을 때 어디가 틀렸는지 알 수 없다** | 일정 표 (7주 분포) | 안승현 |
| 4 | **역할 분담** ★ | 파이프라인 그림에 이름을 얹는다. **한 사람씩 한 문장** | 아래 그림 | 안승현 |
| 5 | **진행 1 — 기반** | 지난 학기 자산 이식 완료. 뼈대가 돈다 | 숫자 3개 (아래) | 안승현·장원태 |
| 6 | **진행 2 — 시연** ★ | **차가 지정 칸에 들어간다.** 오차 숫자 | **영상 30초** + 오차 표 | 안승현(영상)·김동현(표) |
| 7 | **진행 3 — 인지 접근** | 후보 3개 비교 → 무엇을 왜 골랐나 | 비교 표 1장 | 하수영 |
| 8 | 남은 계획 | M2(11/17) → M3(12/06). 한 줄씩 | 마일스톤 표 | 안승현 |

★ 두 장이 이 발표의 핵심이다. 시간이 부족하면 3번과 5번을 줄인다.

### 4번 슬라이드 — 역할 그림

```
            ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
카메라 4대 →│ BEV 합성│ → │ 네트워크│ → │  기하   │ → │  제어   │→ 주차
            └─────────┘   └─────────┘   └─────────┘   └─────────┘
              안승현        하수영        강도균        안승현
                                                          ↑
                                              ┌───────────┴─┐
                                              │ 측정 · 평가  │ 김동현
                                              └─────────────┘
              장원태 — 이식 · 시뮬 연동 · 프로젝트 관리 (전 구간)
```

한 사람당 한 문장으로 말한다.

- **안승현** — 카메라 4대를 위에서 본 영상으로 합치고, 전체를 잇는다
- **하수영** — 그 영상에서 **주차칸을 찾아낼 모델**을 고르고 돌린다
- **강도균** — 모델이 찍은 점들로 **"칸이 어디에 어떤 방향으로 있다"**를 만든다
- **김동현** — **주차가 얼마나 잘 됐는지를 숫자로** 정의하고 잰다
- **장원태** — 지난 학기 자산 이식, 시뮬레이터 연동, 일정 관리

> **"측정"을 따로 그린 이유를 한 문장 덧붙이면 좋다** — 성공의 정의가 없으면 나머지
> 넷이 나아지고 있는지 알 수 없어서 별도 축으로 뒀다. 심사자가 좋아하는 종류의 답이다.

### 5번 슬라이드 — 숫자 3개

발표 직전에 실제 값으로 갱신한다. 9/23 기준 값:

| | 값 |
|---|---|
| 이식·정비한 코드의 단위 테스트 | **193개 통과** (ROS·GPU 없이) |
| 재사용 패키지 | BEV 합성 · 수집 · 학습 · HD맵 시각화 |
| 정합성 검사기 | 3개 (토픽 계약 · import · 런치 파라미터) |

"백지에서 시작하지 않았다"를 한 장으로 보이는 게 목적이다.

### 6번 슬라이드 — 시연

**이 발표에서 가장 강한 장면이다.** 나머지가 다 부실해도 이게 되면 발표가 산다.

- 영상 **30초 내외.** 시작 자세 → 후진 → 정지까지. 배속을 써도 된다
- 옆에 오차 표 한 장 (`vip3_eval` 출력)

| 항목 | 값 |
|---|---|
| 코너 최대 오차 | ? cm |
| heading 오차 | ? ° |
| 소요 시간 | ? s |
| 충돌 | 0 |

> **인지가 아직 안 들어가 있다는 것을 먼저 말한다.** 숨기면 질문에서 드러나고,
> 먼저 말하면 "단계를 나눠서 하고 있다"가 된다.

### 7번 슬라이드 — 인지 접근

하수영의 1블록 산출물이 그대로 한 장이 된다.

| 후보 | 입력 | 출력 | 사전학습 | 선택 |
|---|---|---|---|---|
| | 원근 / BEV / fisheye | 마스크 / 코너점 / 박스 | ○/✗ | |

**"이식해 온 TwinLiteNet+ 를 왜 안 쓰는가"를 한 줄 넣는다.** 입력이 원근 영상이고
출력이 픽셀 마스크라 주차칸의 직각·규격 성질을 쓸 수 없다 —
가져온 것을 검토해서 걸러냈다는 뜻이라 오히려 점수가 된다.

### 시간 배분 (실질 7분 기준)

```
1 표지          10초
2 무엇을         50초
3 왜 좁혔나      40초
4 역할 분담 ★   90초   ← 가장 길게
5 진행-기반      40초
6 진행-시연 ★   90초   ← 영상 30초 포함
7 진행-인지      60초
8 남은 계획      40초
                ────
                 7분
```

### 예상 질문

| 질문 | 답의 방향 |
|---|---|
| 왜 칸을 지정하나? 실제로는 골라야 하지 않나 | 맞다. **다음 단계다.** 7주에 확실히 끝낼 범위를 먼저 잡았고, 칸 선택은 인식이 되면 그 위에 얹는다 |
| 왜 그 모델인가 | 7번 슬라이드의 표. **사전학습 가중치 유무**가 7주 프로젝트에서 가장 컸다고 말하면 된다 |
| LiDAR 는 왜 안 쓰나 | 센서셋에 있고 받고 있다. 주차칸 **선**은 높이가 없어서 LiDAR 로 안 보인다. 장애물 쪽으로는 쓸 수 있다 |
| 시뮬레이터라 쉬운 것 아닌가 | 시뮬이라 **정답을 알 수 있어서 학습 라벨과 평가 기준이 공짜**라는 게 이점이다. 인식 문제 자체는 같다 |
| 실패하면? | M1(인식 없이 주차)이 이미 되므로 **최소 시연은 보장**된다 |
