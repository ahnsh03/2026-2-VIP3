# 역할과 오너십

사용자가 확정한 역할을 기준으로 한다. 안승현·장원태는 전체 관리와 MORAI 질의 대응을 지원하며, 세 개발자의 구현 업무를 별도 파트로 더 맡는 것으로 계획하지 않는다.

| 담당 | 책임과 인수인계 | 주 작업 경로 |
|---|---|---|
| **강도균** | 제공 GT로 경로 생성·추종·정차 개발. 이후 인지 목표를 같은 계약으로 연결 | `src/vip3_parking/`의 GT·평가, 이후 경로·추종 구현 |
| **김동현** | ROS bridge, 수신·시각 진단, bag 수집·재생, 상태 전달 | `src/vip3_bringup/`, `src/vip3_data/`, 연결용 `scripts/`, `src/vip3_parking/scripts/` 상태·기어 배선 |
| **하수영** | SVM 보정·합성, SS-PSD 공개 모델 적용, 좌표 변환, 라벨 규칙·소규모 학습 | `src/vip3_perception/`, 인지용 `scripts/`, 선택 모델·가중치 명세 |
| **안승현** | 센서셋 최종 관리, MORAI 환경·좌표 검증, 파트 간 질의·통합 조율 | `config/morai/`, `config/ros/`, `docker/`, 공용 bringup·GT 좌표 기준 |
| **장원태** | 발표자료 제작·발표, 전체 진행 관리·질의 대응 지원 | 발표 자료, 이 문서의 진행 결과 요약 |

경로 오너십은 수정 금지가 아니라 충돌을 줄이는 기준이다. 공용 코드는 영향받는 담당자에게 변경 내용을 남긴다. 기어 노드 구현·연결은 김동현, 주차 중 기어 요청 정책과 `/ctrl_cmd` 발행은 강도균이 책임진다. 차량 제원·좌표 기준 변경은 안승현과 함께 대조한다.

## 공통 계약

- 토픽·프레임·메시지 변경은 생산자와 소비자가 함께 확인한다. 현재 구현과 예정 계약은 [시스템 문서](../system/design.md)에 구분한다.
- 센서 export가 바뀌면 JSON뿐 아니라 topics YAML, SVM, static TF, 수집 메타데이터까지 검토한다.
- 자기 파트가 실행되면 [commands.md](../commands.md)에 **실행 위치·선행 조건·명령·출력·종료법·확인일**을 추가한다. 성공 화면만 올리지 않고 재생 가능한 입력을 공유한다.
- 인수인계에는 커밋, 명령, 데이터 run ID/해시, 확인 결과, 남은 제약을 적는다. 문제를 재현할 bag은 별도 팀 저장 공간으로 전달하고 Git에는 넣지 않는다.

## Git 작업

기존 방침은 **자기 담당 영역의 작은 변경은 `main` 직접 push**, 공용 설정·메시지·Docker나 통합 변경은 짧은 브랜치와 PR이다. 공용 변경마다 짧은 작업 브랜치를 만들고 검증 후 `main`에 합친다. 완료된 브랜치 이름을 현행 문서의 실행 기준으로 남기지 않는다. 패키지 경로 변경은 [리팩토링 계획](src-refactoring.md)에 따라 인수인계한다.

```bash
git status --short
git switch main                 # 작업물이 없는 상태에서
git pull --ff-only
# 자기 영역 수정·검증 후 실제 바뀐 경로만 stage
git add <변경한-경로>
git commit -m "feat(parking): 전방주차 경로 생성"
git push origin main
```

push가 거절되면 커밋을 보존하고 최신 원격 변경을 반영한다. 공유 브랜치에 force push하지 않는다. 기능 커밋에 필요한 문서도 함께 넣고, 긴 일지 대신 현재 계획과 실행법을 갱신한다.
